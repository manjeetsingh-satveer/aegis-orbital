# Architecture

AEGIS is a Next.js 16 application with a small server surface and a
computation-heavy client. This document covers the module boundaries and the
non-obvious decisions behind them.

## Layout

```
app/
  api/satellites/     combined CelesTrak feed — what the console consumes
  api/tle/[group]/    per-group feed — public API surface
  api/geo/            coastline geometry, decoded server-side
  layout.tsx          fonts, metadata, Open Graph
  page.tsx            mounts the console
  error.tsx           route-level error boundary
proxy.ts              CSP and document cache control

components/console/   React shell: panels, feed, sandbox, tabs
components/ErrorBoundary.tsx

lib/
  orbital/            TLE parsing, SGP4, orbit classification, CelesTrak client
  detection/          Isolation Forest, telemetry model, metrics, evaluation
  renderer/           canvas: projection, label placement, globe renderer
  simulation/         reducer driving the threat sandbox
  hooks/              client data loading
  api/                route-handler helpers (rate limiting)
  rate-limit.ts       fixed-window limiter
  theme.ts            colour tokens shared by React and canvas

e2e/                  Playwright specs, run against a production build
scripts/              evaluation and fallback-snapshot generators
legacy/               the pre-3.0 single-file build, kept for reference
```

## The React / canvas split

This is the most important constraint in the codebase.

The globe renders roughly 120 satellites at 60fps. If those positions lived in
React state, the app would dispatch on the order of 10,000 state updates per
second and stall. So `lib/renderer/globe-renderer.ts` is a plain TypeScript
class that owns its own `requestAnimationFrame` loop and its own canvas. React
mounts it once and never re-renders it.

Data flows **in** through imperative setters (`setSatellites`, `setThreatIds`,
`setSelectedId`). Events flow **out** as discrete callbacks — selection only.
Nothing per-frame crosses the boundary.

```
React  ──setSatellites/setThreatIds──▶  GlobeRenderer  ──onSelect──▶  React
 (chrome, panels, alert feed)            (owns rAF, canvas)          (dispatch)
```

A corollary: the renderer must never be reconstructed on prop changes. The
`onSelect` callback is held in a ref, synced in an effect, so a new callback
identity does not tear down and rebuild the renderer mid-flight.

Pure logic is deliberately extracted out of the renderer class so it can be
tested without a canvas — `projection.ts` (orthographic projection, antimeridian
interpolation) and `labels.ts` (formatting, collision rejection, priority
ordering) are both fully unit-tested.

### Rendering performance

- SGP4 runs at 10Hz, not per frame. Each tick propagates to *now* and to
  *now + 100ms*; frames interpolate between two exact solutions rather than
  extrapolating from one. A LEO satellite moves under 0.1° in 100ms, so this is
  visually identical at a sixth of the cost.
- The starfield, milky way, and sun are drawn once to an offscreen canvas and
  blitted per frame, replacing ~430 `arc()` calls and two gradients.
- Coastlines are built into a single `Path2D` once per frame and filled three
  times. The predecessor re-projected every vertex for each of its three passes;
  projection is the expensive part.
- Hit-testing reuses the screen positions computed during the last frame, so a
  click cannot disagree with what the user actually saw.

## Data flow

```
CelesTrak ──▶ lib/orbital/celestrak.ts ──▶ app/api/satellites ──▶ useSatellites ──▶ GlobeRenderer
              (fetch cached 1h,            (Zod validation,        (retry+backoff,   (SGP4 @ 10Hz)
               names sanitised)             rate limited)           initSatellite)
```

The server does the fetching. That single decision removes the CORS constraint,
which removes the need for third-party proxies, which removes the injection sink
that came with them — and lets the CSP be `default-src 'self'`.

**Caching sits on the upstream fetch, not the route.** Caching the route made
its handler static, so the per-request rate limiter never executed. Caching the
CelesTrak call instead keeps upstream load at one request per group per hour
while leaving the route dynamic so request-level controls still run.

**Degradation is explicit.** When CelesTrak fails, the route falls back to
`lib/orbital/fallback-tles.json` — a snapshot of real elements with valid
checksums, regenerated by `npm run refresh:fallback`. The response reports which
groups degraded, and the UI says so. Element age is carried through to the UI,
which derives a stated position accuracy from it rather than quoting a fixed
figure that would silently become false as the snapshot ages.

## Detection

`lib/detection/isolation-forest.ts` implements Isolation Forest (Liu, Ting &
Zhou, ICDM 2008): random split trees over subsamples, scoring by normalised path
length `2^(-E(h(x))/c(n))`. It is pure, seeded, and deterministic — the same
seed and data always produce the same forest, so results are reproducible and
test failures are debuggable.

Training uses nominal traffic only; the algorithm assumes a predominantly-normal
training set, and contaminating it with attacks teaches the model that attacks
are unremarkable. The alerting threshold is fixed from the *training* score
distribution at 99% specificity, so it never sees the test set.

`npm run evaluate` writes `lib/detection/evaluation-results.json`, which the UI
imports. CI regenerates it and fails if the committed numbers no longer match a
real run — the accuracy figure on screen always corresponds to a run that
actually happened.

The telemetry itself is simulated and labelled as such throughout. Real operators
do not publish uplink SNR or telecommand rates.

## Simulation state

`lib/simulation/reducer.ts` reduces over one immutable state object. This is a
direct response to how the predecessor failed: state lived in a dozen mutable
module globals plus a `setTimeout` handle, and reset cleared only some of them —
leaving the phishing timer running, the attack counters populated, and the threat
score pinned.

Reducing makes those bugs unrepresentable. `reset` returns `INITIAL_STATE`
wholesale, and the phishing timer lives in an effect keyed on `phishStage`, so a
state change cancels it through normal effect cleanup rather than through
remembering to call `clearTimeout`.

The threat score decays with a 45-second half-life instead of accumulating
monotonically, so the board recovers the way a real console would.

## Testing

| Layer | Tool | Covers |
|---|---|---|
| Unit | Vitest | orbital math, detector, metrics, reducer, projection, labels, rate limiter |
| End-to-end | Playwright | hydration, simulations, reset, a11y, API contract, security headers |

E2E runs against a **production build**, not `next dev`. This is not incidental:
dev mode re-evaluates modules per request, which hides real behaviour. Two
production-only defects were caught exactly this way — the rate limiter appearing
inert, and a CSP that blocked every script and prevented hydration.

Coverage thresholds are enforced in CI. The canvas renderer and React hooks are
excluded from unit coverage and covered end to end instead; the pure logic they
depend on is unit-tested directly.
